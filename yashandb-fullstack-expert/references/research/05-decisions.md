## 1. 关键决策与转折点

### 1.1 为什么选择"对标 Oracle"而非 PostgreSQL/MySQL 路线？

**决策背景**：2019 年深算院揭牌，团队由樊文飞从英国爱丁堡大学信息学院带回深圳。当时国产数据库已有两条成熟路径——开源 PostgreSQL/MySQL 二次开发（如 OceanBase 早期、GoldenDB 早期）和基于 Oracle PL/SQL 兼容（如 KingbaseES、DM）。

**决策本身**：
- 选择"Oracle 1:1 平替"为唯一战略主线，深度兼容 PL/SQL、数据类型、系统包、PL 对象。
- 2024 年 11 月正式提出"三个不变，两个对等，一个更优"话术：
  - 三个不变 = 架构 / 应用 / 运维不变
  - 两个对等 = 性能 / 可用性可靠性对等
  - 一个更优 = 安全性更优
- 官方测算 1:1 平替比应用系统重构**降低 50% 总体拥有成本**。

**决策结果**：
- V23.3（2024-11-14 发布）官方宣称 Oracle 兼容性从 90% 提升至 99%；26+ 数据类型 / 40+ 存储过程 / 200+ 系统包 / 130+ 内置函数 / 200+ 字典 / 60+ 动态视图全兼容。
- 2024 年新增 MySQL 兼容（V23.3 兼容 MySQL 5.7，V23.4 LTS 全方位增强），覆盖迁移路径。
- "Oracle 1:1 平替"已成为 YashanDB 在金融行业的标准话术和差异化卖点。

**事后反思**：官方未直接反思，但 V23.3 同时兼容 MySQL 是一个明显的策略补充——纯 Oracle 路线在客户群窄、应用改造成本敏感的场景（如互联网、政务 SaaS）触达有限，加入 MySQL 兼容扩大了潜在客户池。

**信息来源**：新浪科技 2025-03-20《100 项！YashanDB 与 Oracle 全面对比》、掘金/SegmentFault 2024-12 V23.3 发布通稿、东方财富 2024-11-19 国产数据库深圳发布"核心平替"战略。

### 1.2 为什么坚持 100% 自研内核而非基于开源？

**决策背景**：2018-2019 年深算院建立初期，正是国内"开源二次开发 + 加固"路线最盛行的阶段（如基于 PostgreSQL 的厂商集群）。

**决策本身**：
- 内核代码自主率 100%（由工信部电子五所检测）。
- 自研聚合内存技术 **Cohesive Memory**、集群文件系统 **YFS**、集群管理服务 **YCS**、并行可扩展、跨模融合计算等"根技术"。
- 樊文飞公开演讲反复强调："开源二次开发路线无法真正替代 Oracle 核心场景"，并以"基础理论创新 + 自研技术系统"为差异化竞争锚点。

**决策结果**：
- 2022 年获第五届数字中国建设峰会"十大硬核科技"奖（数据库产品奖项）。
- 2025-08-22 通过中国信息安全测评中心"安全可靠测评"（V23 版本）。
- 2025-01 通过北京国家金融科技认证中心"分布式数据库金融标准符合性验证"（337 项测试全过）。
- 通过中国电子学会科技成果鉴定：多项核心技术达"国际领先水平"。

**事后反思**：纯自研路线的代价是商业化前 4-5 年几乎没有收入（2019-2022 是"产品和工程落地期"），靠政府专项资金和研究院体制存活。这一战略选择与樊文飞的院士背景、深算院的政府背景高度相关——它不是普通创业公司敢选的路。

**信息来源**：CSDN 2024-08 YCA 学习记录、Sohu 2025-08-23 新华社报道、SegmentFault 2025-01-15 金融标准验证、东方财富 2024-11-19。

### 1.3 为什么同时做三种部署形态（单机 / 分布式 / 共享集群）？

**决策背景**：高端客户的核心系统（银行交易、运营商计费、政府关键平台）已被 Oracle RAC / DB2 pureScale 占据长达 20+ 年。国产替代选项过去主要是"主备"或"分布式（基于分库分表改造）"，前者无法承受高端负载，后者要重写应用。

**决策本身**：
- 同时铺设单机/主备、分布式（实时数仓）、共享集群（YAC）三条产品线。
- 共享集群（YAC，YashanDB for Cluster）2023-11 首次发布，2024-03 发布首个 LTS 商用集群版本。
- 主张"集中式 + 分布式"两类架构全覆盖。

**决策结果**：
- YAC 4 节点 TPC-C 达 **520 万 tpmC**，2 节点 **300+ 万 tpmC**，线性扩展比 >0.7（官方跑分，非 TPC 官方审计）。
- YAC 在 2024-2025 进入"规模化商用"阶段，应用于数字政府、金融、能源等场景。
- 分布式实时数仓主要承担 OLAP / HTAP 场景。
- 共享集群被定位为"塔尖技术"——是樊文飞体系下对 Oracle RAC 的正面对标。

**事后反思**：三条产品线同时做是典型的高举高打路线，对资源消耗极大（共享集群 + 分布式 + 主备三条产品线的内核团队都要养）。从公开报道看，这是被金融/政务客户需求"反向倒逼"出来的——客户明确表示"我们不接受让你重写应用"。

**信息来源**：SegmentFault 2025-02-26 V23.3 共享集群新特性解读、SegmentFault 2025-04-17 YAC 性能实测、墨天轮 2024-11 V23.3 发布、CSDN 2024-04 V23.2 LTS 发布。

### 1.4 为什么兼容 MySQL 而非 Oracle PL/SQL？（修正：客户问题本身的逻辑反向）

**用户原问题**：为什么兼容 MySQL 而非 Oracle PL/SQL？
**实际决策**：YashanDB 的**主路**恰恰是兼容 **Oracle**，**MySQL 兼容是 V23.3（2024-11）才作为补充加入**。客户问题的命题方向是反的。

**决策本身**：
- 早期版本（V22.2、V23.1、V23.2）几乎只兼容 Oracle。
- V23.3（2024-11）首次加入 MySQL 5.7 兼容形态；V23.4 LTS（2025-08）全方位增强 MySQL 兼容（兼容 5.7-8.0 网络协议、内置 180+ MySQL 同名函数、information_schema/mysql schema 系统视图、Navicat/mysql-jdbc/mysqldump 工具兼容）。

**决策背后的逻辑（官方表述）**：
- "近年来开源软件漏洞和开源软件供应风险事件频发，例如 Apache 日志严重漏洞、Linux xz 压缩工具恶意植入以及最近 Linux 的内核除名俄罗斯的开发者。今年崖山将兼容 MySQL 开源生态作为新的战略方向，旨在为 MySQL 用户提供……"

**决策结果**：
- MySQL 用户可"应用零修改"平滑迁移到 V23.4 LTS。
- 双重兼容策略使 YashanDB 可同时覆盖 Oracle 替换市场（金融/政务）和 MySQL 替换市场（互联网/中小银行/SaaS）。

**事后反思**：从时序上看，YashanDB 先 Oracle 后 MySQL 的策略与金仓（先 PG 后 Oracle）和万里（MySQL 主路）形成鲜明对比——它走的是"先做最难的，下来做补集"路线。

**信息来源**：SegmentFault 2024-12-11 V23.3 重磅发布通稿、博客园 2025-08-04 V23.4 LTS MySQL 兼容性全方位增强、ITPUB 2025-08 V23.4 LTS 发布。

### 1.5 何时决定做共享集群 YAC？为何做 Cohesive Memory？

**决策时间线**：
- 2023-11-08 YashanDB 2023 年度产品发布会首次发布 YAC（YashanDB for Cluster）+ 分布式实时数仓 + 空间数据库三大新品。
- 2024-03 YAC 首个长期维护的商用集群版本发布。
- 2024-11 V23.3 把 YAC 提升到"战略级产品"地位，配套主备集群、两地三中心、逻辑备库。

**Cohesive Memory 的提出**：
- 2024-2025 年公开材料中频繁出现"自研聚合内存技术 Cohesive Memory"——用于消除共享集群跨节点缓存一致性瓶颈，是 YAC 区别于"伪分布"的标志性设计。
- 与之配套的是：崖山集群文件系统 YFS（共享存储）+ 崖山集群服务 YCS（集群管理）。
- 技术指标：RPO=0，RTO<20s，线性扩展比 >0.7，4 节点 520 万 tpmC。

**决策背后**：
- 樊文飞 2024-11 公开演讲："芯片受制于人，未来如果开源软件使用受限，国产基础软件将面临更严峻的挑战……只有坚定软件自主创新，掌握自研'根'技术，才能在基础软件领域真正实现'自立'。"
- 共享集群被官方定义为"卡脖子技术"——是对 Oracle RAC 的正面对标，是国产数据库领域的"硬骨头"。

**信息来源**：至顶网 2023-11-09、东方财富 2024-11-19、SegmentFault 2025-02-26 V23.3 共享集群新特性、Cent 2023-11-10 中国经济新闻网。

### 1.6 商业化路径选择（直销 vs 渠道 vs 集成商合作）

**决策本身**：
- 直销 + 集成商合作"双轮驱动"。在金融行业深绑长亮科技（金蝶生态）、恒生电子、天源迪科、高伟达、金证科技、瑞银科技等头部 ISV/SI；在政务行业深绑深智城集团、丰图科技、超图软件；在企业服务领域联合金蝶云·苍穹。
- 2024-11 启动"金融核心替代技术创新生态共建行动"——联合 12+ 上下游企业（含华为、浪潮、迪思杰、新数科技、云和恩墨、中软国际）。
- 2025-03 与海光信息签署战略合作（CPU + 数据库）。
- 2024-09 与华瑞指数云（ExponTech，SDS2.0）签署战略合作。

**决策结果**：
- 2025-04 获"2024 年度中国信创产业最佳服务商"和"2024 年度中国科技行业新锐企业榜"双项荣誉。
- 公开数据显示"已服务近百家标杆客户"。
- "1+3"产品体系（1 个数据库内核 + 3 个工具平台：开发平台、运维平台、迁移平台）配套生态打法。

**事后反思**：从公开材料看，崖山科技的直销能力相对有限（崖山科技母公司参保 4 人），绝大部分销售/交付依赖"深算院+崖山科技+集成商"的三角结构。这种结构在金融、政务、国央企这些"销售周期长、客户关系重"的场景有效，但在中小客户场景效率低——这也是为什么后来加入 MySQL 兼容（拉低门槛）。

**信息来源**：21CN 2025-04-07 崖山科技入选"年度科技行业高成长企业"、Sohu 2024-11-15 深圳新闻网、CSDN 2024-09-18 华瑞指数云战略合作、CSDN 2026-03-17 海光信息战略合作。

### 1.7 客户选择策略（先做金融还是先做政府？）

**决策本身**：
- **金融优先**——这是行业销售规律决定的（金融客户愿意为"自主可控 + 性能 + 高可用"付溢价）。
- 但实际操作上是"金融 + 政务 + 国央企"三线并行：依托深圳市本地政府关系，先做深圳本地的政务（龙华区数字孪生、市政务短信平台、政府数据开放平台、深圳燃气、深圳地铁、深圳市环境水务、深圳智慧城市集团），同时通过长亮科技等集成商打入金融客户。
- 标志性事件：**2023-11-17** 深圳企业创新发展大会集中签约 7 家企业（珠海华润银行、深圳燃气、深圳环水集团、深圳地铁、深智城、长亮科技、金蝶），签约总金额近亿元。

**决策结果**：
- 2024-12-24 央行数字货币研究所"数字人民币联防联控系统"上线（YashanDB）。
- 2024-04 国信证券 / 申万宏源 / 信达证券 / 国金证券 / 广发证券等头部券商与 YashanDB 在"证券基金信创联盟研讨会"互动。
- 博时基金、华润银行、深圳燃气等被列为"近百家标杆客户"代表。
- 政务侧：深圳市政府数据开放平台、深圳市政务短信平台、龙华区数字孪生城市平台、某三甲医院绩效考核系统。

**事后反思**：从案例细节看，YashanDB 在政务侧的"深耕"反而比金融侧更深（深圳本地政务案例数明显多于金融案例）。这与深圳作为深算院、崖山科技所在地、深圳燃气/华润银行总部/深圳地铁总部都在本地有关。**地理红利 + 政府关系 + 院士背书**构成早期客户进入的核心闭环。

**信息来源**：深圳新闻网 2023-11-17 集中签约、移动支付网 2024-12-24 数字人民币联防联控系统、CSDN 2024-05-07 证券基金信创联盟研讨会、21CN 2025-04-07 高成长企业榜。

## 2. 重大技术里程碑

### 2.1 TPC-C 312 万 tpmC / 520 万 tpmC 测试背景

| 指标 | 数值 | 节点数 | 硬件 | 第三方审计？ | 数据来源 |
|---|---|---|---|---|---|
| 共享集群 TPC-C | **312 万 tpmC**（2 节点）/ **520 万 tpmC**（4 节点） | 2 / 4 | 官方未公开 | 否——是**官方自测 BenchmarkSQL** | 哔哩哔哩 2024-06 / CSDN 2024-12 |
| 单机 TPC-C | "是 Oracle 单机的 1.2 倍，MySQL 的 2.5 倍" | 1 | 官方未公开 | 否 | YCP 学习材料 |
| 共享集群 vs Oracle | "超过主流国际数据库 50%"（发布会现场） | 2 | 128 核 X86 | 否 | SegmentFault 2025-02 |

**重要事实**：
- YashanDB 的 TPC-C 数据**不是 TPC 官方审计**结果——是基于 BenchmarkSQL 工具的自测。
- TPC 官网（tpc.org）的"Top Performance"列表中**没有**YashanDB——可独立验证的 TPC-C 结果截至本调研日期仅 OceanBase、PolarDB、DaMeng 等少数厂商进入 TPC 官网。
- 4 节点 520 万 tpmC、线性扩展比 >0.7 是**厂商自测**；宣称"和 Oracle 同等水平"是基于厂商单方面对比。
- **可独立验证程度**：低。所有 TPC-C 数据均为厂商发布，未见第三方审计报告。

**判断**：作为对外宣讲话术可以引用，但**不能等同于** TPC 官方排行榜上的结果。在向客户方解释时务必明确这一点。

## 4. 商业化与组织

### 4.1 融资历程

**调研结论**：截至 2026-08-01，**公开渠道未发现明确的崖山科技 A/B/C 轮融资新闻**。这与厂商本身的特殊性质有关：
- 深算院是深圳市政府建设的"十大基础研究机构"之一，**财政拨款 + 项目经费**是主要资金来源。
- 崖山科技作为商业化运营主体，注册资本未公开披露。
- 2025-04 获**工信部赛迪顾问"2025 中国最具投资价值基础软件企业榜单"榜首**——这是"投资价值"评估而非"已投资"披露。

**对比同行**：OceanBase 2023 年从蚂蚁剥离独立融资、PolarDB 走阿里云路线、达梦 2024 年科创板上市、金仓（电科金仓）走央企整合路线——崖山走的是"研究院 + 商业公司 + 政府客户"的独特路径。

### 4.2 客户扩展速度

- 2022：数字中国"十大硬核科技"奖（产品阶段）。
- 2023-11：集中签约 7 家深圳本地行业标杆，签约总金额近亿元。
- 2024-12：央行数研所数字人民币联防联控系统上线（首个国家级金融基础设施案例）。
- 2025-04：公开宣称"近百家标杆客户"——**4 年累计**。

**对比**：金仓、达梦同期客户数为数百到数千家（基于更多产品形态 + 渠道分销）。YashanDB 客户数较少但**单客户体量大**——以银行/政务/能源大型客户为主。

### 4.3 团队规模变化

- **深算院**：500 人规模（2024-05 公开口径），研发占比近 9 成。院士 2 人、海外高层次 5 人、长江学者 1 人。
- **崖山科技**（商业化公司）：工行口径参保 4 人——这反映**崖山科技本体只承担商业运营 + 营销 + 部分研发**，绝大部分研发人员劳动关系在深算院。

### 4.4 与深圳计算科学研究院的关系

- 深算院（事业单位）→ 崖山科技（商业公司）："母子关系"。
- 深算院负责理论创新、核心研发、基础研究；崖山科技负责商业化落地、产品包装、客户服务。
- 陈志标身兼"深算院首席技术官 + 崖山科技总裁"双重身份——确保两边协同。
- 樊文飞身兼"深算院首席科学家 + 崖山科技首席科学家"双重身份。
- 这种"一个研究院 + 一个商业公司"的二元结构在中国数据库厂商中是**独特**的（对比金仓/达梦的纯企业路线、OceanBase 的纯互联网路线）。

### 5.3 客户可信度风险

- **数字人民币联防联控系统**：被官方列为"国家级金融设施"。但 30 分钟切换时长是**官方宣称**——缺乏人民银行独立公告佐证。
- **"超过主流国际数据库 50%"**：缺乏统一基准下的可比性测试。
- **"已服务近百家标杆客户"**：客户名单中部分客户（如博时基金、华润银行）仅有集中签约/合作框架，未见具体业务系统上线披露。

### 5.4 行业争议（潜在）

- **路线之争**：开源派（金仓部分 PG、万里 MySQL、HotDB MySQL）与自研派（YashanDB、OceanBase、达梦）的对立是国产数据库行业的"路线之争"。YashanDB 站在"必须 100% 自研"一方。
- **"信创目录"位置**：截至本调研日期，YashanDB 已在多个地方信创目录中，但**未明确是否在中央国家机关信创目录或国资委央企信创目录中**——这影响其市场覆盖。
- **与同行的竞争**：在金融信创市场，YashanDB 直接面对 OceanBase（蚂蚁系）、TDSQL（腾讯系）、GoldenDB（中兴）、GaussDB（华为）、KingbaseES（电科）、DM（达梦）、GBase（南大通用）。在政务市场，面对金仓、达梦的强势渠道覆盖。

## 6. 关键发现摘要

1. **团队"双轨制"是核心决策**——深圳计算科学研究院（500 人事业单位）+ 崖山科技（商业公司 4 人社保）的"研产分离"结构是 YashanDB 最大的组织特征。这种结构让"100% 自研"成为可能，但限制了纯商业化扩张速度。

2. **Oracle 路线 + 共享集群是双重"塔尖"战略**——同时对标 Oracle PL/SQL 兼容和 Oracle RAC 共享集群，是国产数据库领域最艰难也最差异化的定位。金仓、达梦走的是"主路 PG/MySQL 兼容 + 集中式"；OceanBase 走"分布式原生 + 蚂蚁生态"；只有 YashanDB 走"Oracle RAC 兼容 + 100% 自研内核"。

3. **金融优先 + 地理红利**——金融是行业优先（议价能力高），但实际最早落地是深圳本地政务（龙华区、深圳市级）和深圳本地国央企（深圳燃气、环水、地铁）。**院士 + 研究院 + 龙华区共建**三位一体的地方关系是早期客户突破口。

4. **TPC-C 数据的可验证程度低**——所有"520 万 tpmC / 超过 Oracle 50%"等数字均为厂商自测（TPC 官网无 YashanDB 记录）。在与客户沟通时必须澄清"是 BenchmarkSQL 自测、非 TPC 官方审计"。

5. **2023-11-17 集中签约是商业化分水岭**——7 家深圳本地企业近亿元签约标志 YashanDB 从"研究院阶段"进入"规模化商业阶段"；2024-12 央行数研所案例标志进入"国家级金融基础设施"。

6. **MySQL 兼容是 2024-11 之后的关键补集**——V23.3 / V23.4 LTS 加入 MySQL 5.7/8.0 兼容，明显是为补 Oracle 路线的客户覆盖盲区（互联网、SaaS、中小型客户）。这是从"塔尖"向"塔基"扩展的策略信号。

7. **运营商案例在本调研范围内为空白**——未发现中国移动/联通/电信的核心案例。这与三大运营商在数据库国产化主要选择 OceanBase/TDSQL/GoldenDB 的格局一致。

8. **金融核心案例"披露深度不足"**——央行数研所 + 国信证券 + 博时基金 + 华润银行名单中，**只有央行数研所有具体技术细节**（数字人民币联防联控系统）。其他金融客户的"真实生产规模、稳定性记录、性能数据"公开材料极少。

9. **安全可靠测评（2025-08-22）+ EAL4+ + 商密认证**——构成了金融/政务/央国企客户准入的完整资质栈。V23 系列已通过中国信息安全测评中心 + 国家保密科技测评中心联合发布的"安全可靠测评"。

10. **樊文飞院士是 YashanDB 商业故事的灵魂人物**——从命名（崖山、采石矶、钓鱼城）、到理论原创（有界计算、跨模计算、近似计算）、到国家院士背书、到"自强/自立/自信"的话语体系，樊文飞个人 IP 在 YashanDB 商业化中权重极高。**陈志标**则是工程化与商业化的核心操盘手。客户原始问题中的"俞翔"在公开材料中**未出现为创始人或核心高管**，可能为调研对象记忆错误，建议纠正。
