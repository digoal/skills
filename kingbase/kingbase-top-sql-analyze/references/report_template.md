# 报告输出模板

```markdown
# KingbaseES TOP SQL 性能分析报告

## 采集元信息

- 实例：<host脱敏，如 xxx.xxx.***.***>:<port> / 数据库：<dbname>
- 连接后端：python SDK (psycopg2/psycopg) / psql shell
- 采集模式：差值模式 / 重置模式
- 快照1时间：YYYY-MM-DD HH:MM:SS
- 快照2时间：YYYY-MM-DD HH:MM:SS
- 采集间隔：X 分钟
- KingbaseES 版本：X.Y（server_version_num=...，PG 兼容模式）
- sys_stat_statements 扩展版本：1.x
- sys_stat_statements.track：all / top / none（提示信息如适用）
- sys_stat_statements.max：N（采样容量提示如适用）
- track_io_timing：on / off（off 时 IO 耗时维度不可用）
- 本次可用维度：<列出；被跳过的维度及原因>
- 本次剔除的数据不连续记录数：N 条

## 一、总耗时 TOP 10

| 排名 | SQL(截取) | 用户 | 执行次数 | 平均耗时(ms) | 总耗时(ms) | 缓存命中率 | 返回/影响行数 | 写放大(脏块) |
|------|-----------|------|----------|--------------|------------|------------|----------------|--------------|
| 1 | ... | ... | ... | ... | ... | ... | ... | ... |

（其余 6 个维度表格结构相同：单次最慢 TOP10 / 执行频率 TOP10 / 总IO消耗 TOP10 / 写放大 TOP10 / 单次返回行数异常 TOP10 / 总扫描行数 TOP10。
 注：KES V9R1C10 无 wal_bytes 字段，「写放大 TOP」以 shared_blks_dirtied 为口径。）

## 二、逐条优化建议

### [维度名] 排名1: <SQL摘要>

- **性能摘要**：一句话概括
- **问题诊断**：命中的诊断方向（仅列实际命中项）
- **具体建议**：可执行 SQL / 改写建议
- **预估收益**：高 / 中 / 低 及理由

（按维度 TOP3 重复，跨维度重复出现的 SQL 只展开一次，注明「该 SQL 同时出现在 XX、XX 维度」）

## 三、综合汇总

### 健康评分：XX / 100

- 缓存命中率得分：XX/30
- 平均执行时间得分：XX/30
- 全表扫描比例得分：XX/20
- 写放大合理性得分：XX/20

### Top 3 最值得优化的 SQL

1. <SQL摘要> —— 理由 & 预期收益
2. ...
3. ...

### 整体负载画像

一句话总结（如「读密集型，Top SQL 中 60% 存在全表扫描迹象」或「写入密集型，写放大集中在 3 条批量 UPDATE」）

## 四、局限性说明

- 本次分析基于的采集模式、间隔、剔除记录等局限性列表
- 若干条建议标注了「基于统计信息推测，未经执行计划验证」，需要进一步确认
- 若 track 非 all / track_io_timing=off / 字段缺失导致维度跳过，在此说明
```
