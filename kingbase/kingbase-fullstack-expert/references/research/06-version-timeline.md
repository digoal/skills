- **R6C3 (2021-03~05)**：V8R6 早期形态，主备流复制、读写分离集群

- **R6C6 (2022-06~09)**：国产 CPU/OS 深度适配、生态工具兼容
- **R6C7 (2022-11~2023-03)**：安全、IPv6、多模数据
- **R6C8 (2023-09~2024-06)**：性能与备份恢复增强
- **R6C9 (2024-10)**：V8R6 末班版本，2024 年生态突围

## 三、PG 内核对应关系表

| KingbaseES 版本 | PostgreSQL 内核 | 兼容模式 | 官方说明 |
|---|---|---|---|
| V8R2 / V8R3 | PostgreSQL 9.6 | PG 模式默认 | "KingbaseES-8.2 和 PostgreSQL 高度兼容，进程模型与 PG 9.6/10 一致"（CSDN 官方文档披露） |
| V8R6（2021~2024） | PostgreSQL 12 | 通过 `pg_compat_version = '12'` 切换 | 官方文档在 `pg_compat_version` 中显式标注 PostgreSQL 12 锚点 |
| V9R1（2022~2024） | PostgreSQL 12 | V9R1 仍以 PG 12 为主 | CSDN 提示"建议设为 PostgreSQL 12，覆盖 90% 以上常用语法" |
| V9R2（2024-11~2026-Q1） | PostgreSQL 12~13 | 升级 13 | 综合官方文档与版本号推断 |
| V9R3（2025，MySQL 兼容版） | PostgreSQL 13~14 | 多语言兼容 | 官方 |
| V9R4（2025-Q4，SQL Server 兼容版） | PostgreSQL 13~14 | 多语言兼容 | 官方 |
| KES V9 2025（融合数据库） | PostgreSQL 14 | 多语法一体 | 官方媒体披露 |

> **关键参数**：`pg_compat_version` 显式控制 PG 语法兼容版本（V8R6/V9R1 推荐设为 `'12'`），过高版本可能触发未实现函数报错。

## 八、升级路径与兼容性变化

### V8 → V9 升级路径

- **数据迁移**：可通过 KDTS（金仓数据库迁移工具）实现 V8R3 → V8R6 → V9R1 → V9R2 的平滑迁移
- **应用兼容**：V9 保留 V8 全部 API，应用代码无需修改
- **配置兼容**：`kingbase.conf` / `sys_hba.conf` 兼容，但建议显式设置 `pg_compat_version = '12'`
- **存储兼容**：V8R6 → V9R1 物理存储格式可直接升级（`sys_upgrade` 工具支持小版本升级）

### 兼容模式矩阵

| 兼容模式 | 目标数据库 | 关键参数 |
|---|---|---|
| PG 模式 | PostgreSQL | `compatible_mode = 'postgresql'`、`pg_compat_version = '12'` |
| Oracle 模式 | Oracle | `compatible_mode = 'oracle'`、`enable_ci=off`、`enable_upper_colname` |
| MySQL 模式 | MySQL | `compatible_mode = 'mysql'` |
| SQL Server 模式 | SQL Server | V9R4 主打 |
